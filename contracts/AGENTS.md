# `contracts`

> The nearest `AGENTS.md` governs this subtree. It extends the root
> [`AGENTS.md`](../AGENTS.md) rather than replacing it, and loses to executable
> code, tests, generated contracts, and CI whenever prose is stale.

`openapi.json` and `fixtures/analysis-v1` are the published `analysis-v1` wire
contract. Nothing here is written by hand: both are emitted from the Rust types
in `crates/repolens-server/src/contract` and regenerated by the commands in the
root file. A hand-authored example drifts the moment a DTO changes, and drifts
silently because nothing compiles it.

Fixtures are evidence, not illustration. They are type-checked against the
generated schema in TypeScript and byte-compared against the Rust types in
Cargo, so the same eight files fail the build at both ends.

## Casing

Object fields carry no `rename_all` — Rust already produces `snake_case`, and an
attribute that must be repeated on every DTO is one that will eventually be
forgotten on one. Enum values need the rename, because `PascalCase` variants
cannot produce `SCREAMING_SNAKE_CASE`; it is applied once per enum, never per
variant.

## What must stay representable

Removing any of these is a contract regression even when every test still
compiles:

- **Machine error codes are stable.** `ErrorCode` is a closed set clients switch
  on; the human message is never the thing branched upon.
- **Unresolved fields are nullable and required.** `commit_sha` and
  `composition` use `#[schema(required)]` so a consumer cannot skip the null
  case — the case that matters. Optional-and-absent would let it.
- **Retry permission is server-decided.** `retry.allowed` carries a reason and
  is never inferred from a state name: `FAILED_RETRIABLE` describes the kind of
  failure, not whether the server would accept another attempt.
- **Finding order is server-decided and deterministic.** No client-side sort can
  restore an order the server never fixed.
- **Evidence is bounded**, with the published `maxItems` tied to the bound the
  producing type actually enforces.
- **Limitations are first-class.** Every state where evidence was unavailable
  says so in the payload rather than by omission — including the
  LOC-unavailable case, which has its own fixture.
- **Version metadata travels with the report**, so a reader can tell "the
  repository changed" from "RepoLens changed".
- **`MISSING` and `UNABLE_TO_VERIFY` stay distinct**, as do severity and
  confidence.

## Unknown values are specified, not left to chance

A statically hosted frontend outlives the build it was compiled against, so the
API can gain a variant months after a browser cached the bundle. The rule is
render-in-a-neutral-fallback-naming-the-raw-value: never crash, never drop
silently. `UNKNOWN_VARIANT_POLICY` states it and a contract test fails CI when a
variant is added without frontend handling.

## Review

A change to any file here is an API change. It needs review from both backend
and frontend ownership, and the pull request should name which fixture changed
and what a deployed client compiled against the old shape would now do.
